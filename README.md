# Frikøbsberegner

A calculator for budgeting **frikøb** — externally funded research buy-outs — for research
administrators at a university faculty. Frikøb arithmetic runs in both directions and mixes money,
months, and hours across three incompatible hour bases (payroll, workload norm, billable), so the
same number means something different depending on which of those it's expressed in. The tool's
job isn't just to produce a figure — it's to produce a cited, step-by-step derivation an
administrator can paste into a project budget and defend to a funder.

## What it does

- Converts between kroner, months, and registered hours in any direction, from whatever the user
  already knows.
- Renders a full derivation trace: every intermediate value, the formula that produced it, and a
  citation to the source document and clause it comes from.
- Handles part-time employment fractions, teaching-only buy-outs (priced differently from full
  buy-outs), and date-versioned constants — the underlying norms changed in 2024, so a scenario
  dated before that uses the old figures automatically.
- Reproduces the rounding behavior of the paper-era source documents exactly, including their
  particular rounding *direction* (always in the institution's favor), even though the internal
  math is done unrounded until the point of display.
- Segments multi-year projects into one row per calendar year, compounding budget indexation
  correctly across year boundaries instead of treating the whole project as a single flat period.
- Optionally builds out the full cost stack on top of a scenario — overhead, profit margin, moms,
  and a market-floor check — for the mechanisms (IDV, tilskudsfinansieret, samfinansieret) that
  actually require it; off by default, since most frikøb calculations don't need it.
- Computes the separate PI teaching-credit a senior researcher can claim for postdoc positions
  they've brought in funding for (Princip 6) — a distinct calculation from a personal frikøb, since
  it reduces the grant-winner's own obligation, not the postdoc's.

## Architecture

The calculation logic lives in `src/lib/frikoeb/` as a framework-agnostic core with no dependency
on React, Next.js, or the filesystem — it's pure functions over branded numeric types (an hour is
never accidentally added to a month). Everything the UI shows is generated by this layer; the UI
itself performs no arithmetic of its own.

A few decisions worth noting:

- **The derivation trace is built *before* the arithmetic runs**, not stitched together
  afterward — the trace builder is threaded through every conversion primitive, so it's
  structurally impossible to compute a number without also recording how it was computed.
- **A bidirectional solver** rather than three separate calculators: given any one known quantity
  (money, months, or hours) and a target position, it derives the other two through the same
  conversion graph, so the three directions can never silently drift out of sync with each other.
- **Multiple rounding profiles**, versioned by date, each reproducing a specific historical
  document's published figures byte-for-byte — verified against golden fixtures pulled directly
  from those documents, alongside property-based tests (fast-check) checking that a money → hours
  → money round trip never drifts by more than half a krone across hundreds of generated cases.
- **Config values carry their own citation** — every constant is typed with the document and
  clause it comes from, so a number can never appear in the UI without a source, and an unresolved
  constant fails loudly (`null`, surfaced as "missing data") rather than silently defaulting.

## Auth

Account creation and login are self-serve (username + password, bcrypt-hashed), with no
third-party email service in the loop. Sessions are a signed, stateless cookie — the payload is
verified with an HMAC rather than looked up against a database — so the auth check on every
request doesn't cost a database round trip. Usernames are case-insensitive; passwords aren't.
Accounts can change their own password or delete themselves entirely from a self-service page.

## Stack

Next.js 16 (App Router, Turbopack, Server Actions) · TypeScript · Tailwind CSS 4 · Prisma 7 over
Postgres (Neon, EU region) · Vitest + fast-check for testing · deployed on Vercel.

## Testing

169 tests covering the calculation core: golden fixtures reproducing every worked example from the
source documents exactly, solver round-trip properties, part-time scaling against hand
calculations, multi-year indexation/segmentation, the PI teaching-credit calculation, and
guardrails that make invalid states (an unspecified teaching share, a beyond-range employment
fraction) throw instead of silently defaulting.

```bash
npm test          # vitest, 169 tests
npm run lint        # eslint
npm run typecheck    # tsc --noEmit
```

## Deployment

Deployed on Vercel, with Postgres on Neon (EU region). Environment variable changes require a
redeploy to take effect; migrations run against the direct (non-pooled) connection string, the
app itself against the pooled one.

## Running locally

```bash
npm install          # runs `prisma generate` via postinstall
npm run dev
```

Needs a Postgres connection string in `.env.local` as `DATABASE_URL`, plus an `AUTH_SECRET` (any
long random string — used to sign session cookies). Then either sign up through the app's own
`/signup` page, or seed an account directly:

```bash
npx tsx scripts/create-user.ts <username> <name> <password>
```

## Source documents

Every constant in `src/lib/frikoeb/config/` cites the Aarhus University document it comes from
(working-time agreement, institute frikøb notes and policy, cost-price rate catalogues, IDV overhead
rates, salary agreement). **Those documents are not included in this repository.** They are AU's
material, several come from staff-only pages, and some name individual staff. The topic analyses
derived from them are in `rules/NOTES-*.md`.

To run the app with working citation links, put the original files in `rules/` and copy them to
`public/kilder/`, using the filenames referenced by `DocumentRef.file` in the config. Both
locations are git-ignored for PDFs/spreadsheets. Without them, the calculator works fully; only the
"download source" links on citations return 404.
